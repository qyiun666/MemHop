**版本**：v0.12.1

**类型**：开发规格（面向实现者）

## 概述

v0.12.0 完成了编码器（Candle）、上下文匹配（ActiveContextSet）、自动压缩（compress_plan）三项工程改进。但产品模型中的三个核心抽象——树实体、纠缠事件、三观模式——仍未落地。

v0.12.1 分三个模块实现这三个抽象。树是地基，纠缠是灵魂，三观是果实。

## 模块一：Tree 实体

### 为什么要做

当前 `tree_path: Option<String>` 只是一个字段标签。它不是实体，不能：
- 统计该树下有多少记忆
- 记录最后一次活跃时间
- 关联书架来源
- 作为 recall 的独立维度

### 数据结构

```rust
// memhop/src/tree.rs（新建文件）

/// 知识树 —— 人脑中的一个领域（工作、旅游、孩子...）
pub struct Tree {
    /// 唯一标识，格式 "tree_<timestamp>"
    pub id: String,
    /// 显示名称，例如 "工作"、"旅游"
    pub name: String,
    /// 领域标签，用于自动匹配，例如 "work"、"travel"、"parenting"
    pub domain: String,
    /// 可选的描述
    pub description: Option<String>,

    // 统计
    pub memory_count: u64,       // 该树下的 engram 总数
    pub last_active_at: i64,     // Unix ms

    // 关联
    pub shelf_paths: Vec<String>, // 关联的书架目录路径

    pub created_at: i64,
}

/// 知识树引用（嵌入在 Engram 中，替代 tree_path 字段）
pub struct TreeRef {
    pub tree_id: String,         // → Tree.id
    pub tree_name: String,       // 反范式化，避免 join
    pub tree_domain: String,
}
```

## 模块二：EntanglementEvent 纠缠事件

### 为什么要做

当前 `AssociationKind::CrossTree` 是 pairwise 边：A→B 和 B→C 各自独立，无法表达"A+B+C 在同一次认知迁移中共同参与了一个事件"。  

纠缠事件是 MemHop 和向量数据库的本质区别。

### 数据结构

```rust
// memhop/src/entanglement.rs（新建文件）

/// 纠缠事件 —— 一次跨树认知迁移的记录
pub struct EntanglementEvent {
    /// 唯一标识
    pub id: String,

    /// 参与纠缠的记忆节点（至少 2 个，至少来自 2 棵不同树）
    pub nodes: Vec<String>,

    /// 跨了哪些树
    pub tree_ids: Vec<String>,

    /// 纠缠描述（用模板或 LLM 生成）
    pub context: String,

    /// 触发方式
    pub trigger: EntanglementTrigger,

    /// 强度 0-1，每次再次命中 +0.2，30 天未命中 ×0.9
    pub strength: f32,

    /// 关联的 Plan（如果有）
    pub plan_ids: Vec<String>,

    pub created_at: i64,
    pub last_hit_at: i64,
    pub hit_count: u32,
}

pub enum EntanglementTrigger {
    /// 召回时跨树命中
    RecallCrossTree,
    /// Plan 压缩时发现跨树模式
    PlanCompression,
    /// Dream REM 阶段发现
    DreamEmergence,
    /// 手动标注
    Manual,
}
```

### LMDB 存储

```
表名: entanglement_events
Key:  "ent:<event_id>"
Value: bincode 序列化的 EntanglementEvent

索引:
  反向索引 "ent_node:<engram_id>" → Vec<event_id>
  用于 recall 时快速查找某 engram 参与的所有事件
```

### 创建时机

**时机 1：recall 时自动检测**（brain.rs recall() 末尾）

```
条件：recall 返回结果中 ≥ 2 条来自不同树 → 且 score > 0.8
动作：创建 EntanglementEvent
      context = 模板生成："来自 {tree_a} 的记忆与来自 {tree_b} 的记忆在查询 '{query}' 中关联"
      strength = 0.3（首次创建）
      如果已有同组 nodes 的事件 → 不重复创建，改 hit_count +1, strength +0.2
```

**时机 2：compress_plan 后检测**（brain.rs compress_plan() 末尾）

```
条件：压缩的 plan 涉及的 engram 来自 ≥ 2 棵不同树
动作：创建 EntanglementEvent
      trigger = PlanCompression
      strength = 0.5（Plan 压缩的关联更可靠）
```

**时机 3：Dream REM 阶段**（brain.rs dream_internal() REM 阶段）

```
条件：cross_anchor_discovery 发现跨树语义相似节点
动作：创建 EntanglementEvent
      trigger = DreamEmergence
      strength = 0.2（自动发现的置信度较低）
```

## 模块三：WorldviewPattern 三观模式

### 为什么要做

当 EntanglementEvent 积累到一定数量后，系统应该能涌现出用户的稳定思维模式——即"三观"。

### 数据结构

```rust
// memhop/src/worldview.rs（新建文件）

/// 三观模式 —— 从纠缠事件中涌现的稳定思维模式
pub struct WorldviewPattern {
    pub id: String,

    /// 来源：聚类用的纠缠事件 ID 列表
    pub source_events: Vec<String>,

    /// 模式描述
    pub pattern: String,          

    /// 模式类别
    pub category: PatternCategory,

    /// 统计
    pub occurrence_count: u64,    // 出现次数
    pub stability: f32,           // 0-1，越高越稳定
    pub emerged_at: i64,          // 首次涌现时间
    pub last_reinforced_at: i64,  // 最近一次强化时间
}

pub enum PatternCategory {
    /// 思维风格："先抽象再具体"
    ThinkingStyle,
    /// 价值优先："简洁优先于完备"
    ValuePriority,
    /// 决策倾向："倾向自己实现而非用库"
    DecisionBias,
    /// 审美偏好："喜欢极简设计"
    AestheticPreference,
    /// 情绪模式："遇到阻塞时先散步再回来"
    EmotionalPattern,
}
```

### LMDB 存储

```
表名: worldview_patterns
Key:  "wv:<pattern_id>"
Value: bincode 序列化的 WorldviewPattern
```

### 涌现算法

```
触发：Dream REM 阶段，EntanglementEvent 总数 ≥ 10

步骤：
1. 收集所有 EntanglementEvent（strength > 0.5）
2. 对 event.context 做语义编码 → 向量
3. 余弦聚类（单链聚类，阈值 0.7）
4. 每个类簇：if size >= 5 AND 平均 strength > 0.7 → 创建或更新 WorldviewPattern
5. stability = min(1.0, occurrence_count / 10) × avg_strength
```

### 召回时介入

```rust
// recall() 中新增步骤：

// 查询所有 WorldviewPattern（stability > 0.7）
let worldviews = self.storage.get_active_worldviews()?;

// 附加到结果
for wv in worldviews {
    response.worldview_context.push(wv.pattern);
}

// 认知冲突检测：
// 新输入语义与 worldview 矛盾？
// → 标记为 conflict，返回给调用方
```

```
第一步：Tree 实体（地基）
  新建 tree.rs
  改 engram.rs（TreeRef 字段）

第二步：EntanglementEvent（灵魂）
  新建 entanglement.rs
  改 brain.rs recall()（自动创建 + 展开）
  改 brain.rs compress_plan()（压缩后检测）
  改 brain.rs dream()（REM 阶段创建）
  改 MCP server（新增 3 个 entanglement 工具）

第三步：WorldviewPattern（果实）
  新建 worldview.rs
  改 brain.rs dream()（REM 聚类涌现）
  改 brain.rs recall()（三观介入）
  改 MCP server（新增 3 个 worldview 工具）
```

依赖链：Tree → Entanglement → Worldview。不可跳步。
