# 决策档案: Update 收束记录合并为一次批写

Status: implemented

## Problem

一次轮末收束的多条内容分别落盘，每条都独立承担 flush 与 mmap remap；在保留现有崩溃恢复与重放语义的前提下，热路径存在重复 I/O。

## Decision

轮末收束内容复用同一记录批写原语，整批校验、编码并一次落盘，落盘成功后同步内容镜像；关键词提炼与话题写入仍保持原有顺序。单条写入也复用该原语，归属与缓存维护只有一套。自动序号在批内连续分配前预检占用地址；批写不扩张为事务，失败窗口沿用既有崩溃恢复与重放语义。

## Alternatives considered

- 保持逐条写入：实现与故障语义最熟悉，但每条收束内容都重复支付 flush/remap。
- 把话题也并入同一批：可能再少一次 I/O，但会把 LLM 提炼前后的两个写入阶段改成新事务边界，改变失败语义，超出本次优化目标。
- 重写存储追加协议：没有证据表明收益足以抵偿格式与恢复风险。

## Consequences

- 换来：收束热路径不再为每条内容重复承担 flush/remap，公开 API、返回形状与磁盘格式保持不变；失败时原文保留、重试原地覆写、结果事件按次追加、拒绝零占号与重开读回语义均保持。
- 代价：批写仍不是事务，不能借合并写入收紧既有失败语义；镜像更新必须晚于落盘成功，批内序号仍须预检地址占用。
- 放弃：不把话题写入并入同一批，也不重写存储追加协议；关键词提炼前后的写入阶段与故障边界不变。
