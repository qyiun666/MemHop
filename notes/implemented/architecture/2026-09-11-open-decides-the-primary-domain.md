# 决策档案: Open 以主域画像的存在性决定成败，域身份住在 L0

Status: implemented

## Problem

宿主要拿到一个能干活会话，此前需要三步：打开库、自己建一个 agent 域、把库发号的十六进制域 id 存下来，
再用它换句柄。三步里有两步是纯仪式——域 id 对宿主没有语义，它只是回传给下一个调用的令牌；而「这个库
有没有被初始化过」这件事没有任何一个调用能回答，宿主只能靠「我记得我建过」来判断。

后果在两个地方显形。其一是新库的引导：没有任何入口能在建库的同时写下「这是谁的记忆」，画像只能等库
打开之后再补一次写，中间窗口里读画像得到的是一个空槽，而空槽与「有一个全零画像」在返回值上不可区分。
其二是域身份：一个库里可以同时住着多个 agent，但没有任何字段说明哪个是发起这一切的主 agent、哪些是它
派生出来的子 agent，宿主想按身份分派行为时无从下手。

还有一条更硬的：打开路径把「文件不存在」与「文件存在」压成同一条成功返回，而判 existence 用的那次
`stat` 没有区分失败原因——权限不足或路径是个目录，都会落进「那就建一个新的」分支，而建库是带截断的。
一条写错的配置就能把一个有数据的库清空。

## Decision

- **打开只有一个入口，参数是路径、LLM 端点、调参旋钮与一份可选的主域画像**，返回库句柄。成败由
  「文件在不在」与「主域画像在不在」两件事决定：
  - 文件在、主域画像在 → 成功，传入的画像被忽略（库里的那份是事实源）；
  - 文件在、主域画像不在、传了画像 → 校验后写下，成功；
  - 文件在、主域画像不在、没传画像 → 失败；
  - 文件不在、传了画像 → 建文件、写画像，成功；
  - 文件不在、没传画像 → 失败，**且不留下任何文件**。
- **主域恒为那个隐式的零号域**。它没有注册记录、不可删、恒存在，所以「一个库恰好有一个主 agent」是
  结构性成立的，不需要扫描全部域去数谁声明了自己是主。子 agent 才是注册域。
- **域身份是 L0 画像上的一个字段**，两个值：主 agent 与子 agent。它与画像里那两项由巩固流水线演化的
  字段同等地位——归库所有，宿主写画像时传了也不采信，由建域的那次调用盖章。
- **子 agent 由库句柄上的一个方法建**，参数是它自己的 LLM 端点与一份画像；按画像的名字幂等，同名再调
  即取回既有子域。前置条件是库已打开且主域存在——这两件事由「必须在库句柄上调」天然保证。
- **域 id 从公开面消失**。主域与子域都直接返回会话句柄，宿主不再持有、也不再回传任何域 id；名字是它
  唯一的把手。
- 打开路径改为三态判定，并把校验排在建文件之前：不满足条件时在宿主的路径上不留任何痕迹。

## Alternatives considered

- **把身份写进注册记录的载荷**（载荷从一个裸名字升成带类型的结构体）：注册记录是租户键到域 id 的映射，
  它只在建域与重载映射时被读；身份放这里意味着同一件事在两处各存一份、必须永远一致。更关键的是主域
  **没有**注册记录，所以「名字 → 域」的映射里结构性地不可能出现零号域——身份放在画像上，正好复用这条
  保证；放在注册记录上则要额外写一条「主域不参与名字解析」的规则。零净收益，否决。
- **删掉注册记录，租户键直接从各域画像的名字派生**：单一事实源，名字漂移问题根除。代价是主域的名字
  进入同一个名字空间，必须靠「身份是主就跳过」来防止一个与主域同名的子 agent 请求劫持零号域——一个
  条件判断的疏漏就是跨域串数据；画像损坏的域会连名字一起失去，变成永久不可达的孤儿；而改画像名字
  会变成一次注册表变更，需要在持域锁时再取注册表锁，与既有的锁序相反。风险显著高于收益，否决。
- **主域也走注册记录、由打开时扫描找出身份为主的那个域**：能表达「主域是后来指定的」，但这个灵活性
  没有需求方；换来的是每次打开都要遍历全部域读一条画像，以及「找到两个主」这个需要额外规则去消解的
  状态。否决。
- **子 agent 沿用「建域返回 id、再用 id 换句柄」的两步**：与新入口的形态不一致，且逼宿主继续保管一个
  对它有语义的 id。按名幂等的一步已经覆盖了「建」与「取回」两件事。否决。
- **保留一个按 id 取会话的方法作为逃生口**：那样域 id 就必须继续对外可见，「id 从公开面消失」这条
  收益当场作废。否决。

## Consequences

换到的是：新库的引导与「这是谁的记忆」合成一次调用，不存在画像缺席的窗口；宿主不再保管任何域 id；
「恰好一个主 agent」由零号域的结构性性质保证，而不是一条需要校验的约定；打开路径的三态判定顺带修掉
了一个真实的毁库缺陷——判 existence 失败不再等于「那就重建」。

付出的是：对消费方全面 breaking，入口、句柄类型、方法集与磁盘格式版本同时变，宿主必须跟版；建域、
列域、删域这三个管理方法一并退役，所以子域一旦建了就删不掉，误建的子域只能靠把内容压实到新文件时
筛掉、或换一个文件摆脱；画像的名字同时充当租户键，创建后冻结——宿主改画像名字不影响幂等映射，
用新名字再调会安静地建出第二个子域，这一点只能在文档里讲清楚，库不拦。

磁盘格式版本随之抬升，旧文件在打开时被拒、不迁移。理由是硬的：旧文件里的画像没有身份字段，解码后
每个域都读作主 agent，而新语义要求「恰好一个」——容错打开会直接违反这条不变量，且违反得无声无息。
