# 决策档案: 轮次状态住进域上下文，关闭一轮只有一次调用

Status: implemented

## Problem

宿主把本库接进一个决策循环内核时，必须持有并回传两个 id：`Search` 铸出的场景 id 与
轮次话题 id，然后每一次写入（逐条内容、每一步计划、轮末沉淀）都把这两个键再交回来一次。
这两个键宿主是自己造的（全部由库发号），也从不解释它们，唯一用途是回传；一旦传错，
库要能识别并拒绝——于是「拼错一个 id」成了公开面上一等公民的错误类别，配套一组
归属校验、一组测试和一段宿主文档。

同时，一次轮次的结束在公开面上是三步：逐条 append、再结算。而决策循环的端口只在轮次
终点给一次调用机会，也没有「这一轮属于哪个场景」这个概念。要接上，宿主必须自己造一层
把一次调用摊成三次并保管那两个键。

## Decision

场景与轮次改由域上下文自持（`domain.Context` 的 `Scene`/`Turn` 两个字段，只在域锁内读写），
写入路径不再接受这两个键：

- 轮末一次 `Update` 收下这一轮的收束（刺激、应答、结局），并照旧做一次关键词蒸馏。
  刺激与应答落在该轮话题预留的两个对话槽位上，因此重放一轮是原地覆写而非累积；结局按
  调用次数追加成事件——一次挂起加一次恢复本就是两条事实。
- 逐条内容与计划步骤的写口保留（一次轮次过程中的记录仍是宿主一条条写的），但都不再收键。
  写形状也随这条判据分开：`AppendArchive` 收 `ArchiveInput`（只有宿主真正决定的那八个字段），
  不再收读回来的 `ArchiveSlot`——`ID` 与 `TopicID` 在写侧没有位置，而不是「传了会被丢掉」。
- `Search` 的空场景入参从「每次都新建一条会话」改成「续用该域当前的场景」，跨进程重启
  从记录里恢复；另开一条会话需要一个显式的新建标志。锚点因此只能由**会新建场景的那一读**
  采纳：续用一条会话时递来 `L3ID` 一律拒，不静默丢弃，也不拿它当作「另起一条会话」的暗示。
  自持的那条读路径也不再重复审存在性——紧接着推进轮次计数读的就是同一条记录。
- 删除与合并路径负责同步摘掉自持字段，让一个已毁的轮不可能被下一次收束继续写。
- 读侧补齐同一个判据：`SceneContext` 的空 `sceneID` 读该域自持的那条会话，它承诺零写入，
  因此**不**替一个从没读过的域新建场景。一轮里「问模型之前」的读可以发生很多次，只有开轮
  那一次是 `Search`，其余都走这条纯读——否则决策循环带工具调用时，轮次计数会替根本没发生
  过的轮往前空跳，而那把计数正是轮次 id 的派生依据。

一轮的键若真撞上保留的全零值，`Search` 直接报损坏而不是收下：那个值同时是「没有开着轮」
的哨兵，静默收下等于让宿主写到别人的轮上。

## Alternatives considered

- **让本库 import 决策循环内核、直接实现它的记忆端口**：一步到位消掉转换，但会把跨仓
  依赖引进来，违背两仓互不依赖、只被宿主同时引用的既有边界。落选。
- **新增一个对接子包做适配器**：门面一字不动，但那两个键仍然要跨过门面被回传，转换只是
  换了个地方发生；而且它是既有三段式的第二条通道。落选。
- **保持三段式，把适配代码作为文档示例交给宿主**：改动最小，但每个宿主各抄一份、各自
  保管那两个键，正是本轮要消掉的东西。落选。
- **让轮末那一次调用把整轮内容一并收下（合并逐条写口）**：调用次数最少，但会丢掉「每条
  一个槽位、重放同槽覆写」的逐条幂等——at-least-once 的写循环从单条安全退化成整批重发
  才安全。已由用户裁定否决，逐条写口保留。
- **拿 `L3ID` 非空当作「在这个项目下开一条新会话」的暗示**：省掉一个显式标志，但会话边界
  就由一个副字段决定了，同一个入参在有场景的域与没场景的域上给出两种答案——正是「不猜场景」
  这条要在读路径上守住的判据。落选。
- **每次召回都走 `Search`**：端口两侧形状对称、适配器少一行，但内核一轮里 Think 有 N 次就
  开 N 个轮、只关得上最后那一个，计数白跳 N−1 格。落选，改为纯读侧也认自持场景。
- **适配器自己缓存场景 id 以便重复纯读**：库一字不动，但「宿主不再持键」这条判据恰好在此处
  漏掉一半——读侧留一个键，写侧迟早也会想留。落选。
- **只在入口拒掉非空的归属字段、写读仍共用一个形状**：非 Breaking，也挡住了那条错路，但同一
  形状里这两个字段变成「读回来有、递回去不行」，仍要宿主自己记住；L0 画像那轮已把标准定成
  「没有位置可传」，此处没有理由例外。
- **只在内存里自持、不跨重启恢复**：省掉一次场景枚举，但「一个库就是一个 agent 的会话流」
  就成了只在进程存活期内成立的语义，每次重启都悄悄开一条新会话。落选。

## Consequences

换到了：宿主的接入面收成两个动作——轮初读、轮末写，中间逐条记；写入路径上「传错 id」
这一类错误不再可能，配套的一组归属校验与它的测试面一起消失。时间单位只统一了本库这一侧：
收束入参与其余时间戳同为毫秒并在写边界拒掉秒级带，而决策循环内核自己那个端口仍是 Unix 秒，
那一次换算仍留在宿主填结构体的位置上——不在本仓的裁定范围内。

付出了：域句柄从此带状态，`Search` 与收束调用必须成对、且不能跨轮交替（要交替的写法
是显式点名场景读一次再续）；一轮的收束调用重放时会累积结局事件而不是覆写，读结局的
人要按「一条一次」理解它们；空闲回收会丢掉自持的轮次，因此在收束之前被回收的那一轮
只能由宿主重开——这与旧世界里「开了没结算的轮次没有话题记录」是同一种结局，只是不再
能凭一个键回来补。公开面方法数量不变，但一次面向宿主的破坏性签名变更。
