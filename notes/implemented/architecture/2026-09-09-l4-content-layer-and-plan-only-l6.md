# 决策档案: 一轮的内容同住 L4，L6 只剩计划树

Status: implemented

## Problem

「一轮发生过什么」被劈在两层：L4 存两条对话原文，L6 存轨迹事件与计划节点。两层早就共用
同一个键——`Search` 为这一轮铸出的话题 id——但仍然是两种记录类型、两套域内扫描、两条生命
周期：L4 永久、L6 七天。于是同一件事有两个「哪里能找到它」的答案，L2 话题还得额外持有一份
指向自己原文的引用清单，那份清单是第二真相：它和真正的归档可以不一致，而一旦不一致，读侧
既不能信任它也不能自愈。

分层上也名不副实：L6 名义上是「轨迹」，实际装着两类完全不同的东西——一种是有过程语义的
计划节点，一种是内容（发生了什么的一笔记录）。把内容放在计划旁边，代价是每个读路径都要
先问「这次要不要跨层」，而 Dream 的清理又反过来需要跨层级联，因为节点与事件同住在一份镜像里。

## Decision

- **判据只有一个：内容是内容，计划是计划。** 凡「一轮里的内容」——谁说了什么、发生了
  什么——同住 L4，以 (话题, 种类, 槽位) 寻址；种类只有对话与事件两个值，其余轴（说话者、
  媒介、事件名）与它正交。
- **L6 只承载计划节点**，一节点一条记录：状态机是单节点读-改-写，整树一记录会让每步提交
  变成 O(N) 重写，而被否决的那条路见 `../../rejected/architecture/2026-09-09-plan-whole-tree-record-and-cross-layer-cascade.md`。
- **话题不再持有内容引用**：归档靠自己的话题 id 被寻址，引用清单整段退役。
- 一次格式 bump 让旧文件不可解读（拒开、不迁移），因为「同一条记录在新规则下指向别的
  东西」不属于可以兼容的变更。
- `Update` 因此从「一轮的写者」退成「一轮的读者」，见
  `../simplification/2026-09-09-update-distills-its-own-topic.md`。

## Alternatives considered

- **只在 L6 内部拆两个桶，不动 L4**——落选：读侧仍然要跨两层拼一轮，仍然需要一份镜像同时
  索引两套来源，第二真相只是换了位置。
- **保留 `TrajectorySlot` 与 `ArchiveSlot` 两个类型、只让 L4 索引统管两者**——落选：两种
  记录类型意味着两套 typed reader、两条生命周期与两套字段归属注释，而它们要表达的差别只是
  一个枚举值。
- **让 L4 只存对话、事件永久留在 L6 但共用键**——落选：这正是本次要收掉的口，「一轮的内容在
  一处」变成一句需要读者自行核对的口号。
- **写一个 0x000D→0x000E 的读侧迁移**——落选：旧事件记录的键语义已经改变，迁移等于用新规则
  重放旧数据；库没有可验证的依据保证迁移后指向的还是同一轮。

## Consequences

- 换来：一轮的内容按话题就能取回，一份镜像、一条清理路径、一个「哪里能找到它」的答案；
  跨层级联删除连同它的理由一起消失。
- 放弃：L4 不再是「永久原文层」，它整体受保留窗约束（见
  `../simplification/2026-09-09-l4-seven-day-retention-and-transcript-completeness.md`）。
- 分层叙述同步改口：七层链条里 L6 是计划，L4 是「一轮的内容」。
- 对宿主是破坏性变更（两种记录合一、几个符号消失、旧文件拒开），契约变更只经打 tag 生效。
