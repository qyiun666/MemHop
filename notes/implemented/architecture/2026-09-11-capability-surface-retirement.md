# 决策档案: 能力面整体退役，引擎只做记忆

Status: implemented

## Problem

引擎在能力这件事上还留着两块纯能力：解析校验宿主的能力目录文档（让宿主不必自己维护一份格式解析器），
以及把一轮记下的操作事件提炼成能力候选交回宿主（引擎不落盘，校验、去重、写草稿全归宿主）。这两块是
上一轮把能力记录层整体退役之后剩下的全部——当时的判断是「库不再是事实源，但这两块纯计算对宿主有
价值，留着」。

留着之后暴露的问题不是它们错，而是它们让引擎的边界说不清。引擎的全部语义是「一个 agent 的记忆怎么
存、怎么巩固、怎么读回来」；能力目录是宿主的资产，它的格式、它的激活语义、它落哪个目录，全都是宿主
的决定。一个记忆引擎导出一个「能力文档解析器」，等于对外宣称它知道能力长什么样——而它其实只是替宿主
省了一个 JSON schema 校验。提炼那一块同理：引擎读事件、调一次模型、把候选交回去，全程不存任何东西，
它是一次带提示词的模型调用，恰好住在记忆库里。

代价还有两处具体的。一是依赖图：提炼的实现要引用能力文档的类型定义，而「能力包之间互不引用」是这一层
明文的纪律，这条边一直是个已知的违规。二是公开面上多出八个导出类型与常量，它们只服务这两个方法，宿主
读文档时要在记忆语义里辨认哪些与记忆无关。

## Decision

- **能力面从引擎里整体退役**：解析校验的两个包级函数、提炼方法、能力文档的全部类型与常量、以及只为
  它们存在的内部实现，一并删除。引擎不再导出任何与能力有关的符号。
- **提炼所依赖的「按预算裁剪事件载荷」一并删除**：它的唯一消费者就是提炼，留着即死代码。轮内事件的
  写入上限与读取路径不受影响。
- **轨迹轮次的列举方法一并退役**：它的唯一用途是告诉宿主「哪些轮次记了事件，可以去提炼」，提炼走了
  它就没有读者。按轮读事件轨的能力保留——那是内容层的一个查询条件，不依赖这个方法。
- 能力目录的事实源、格式、激活语义全部回到宿主，与上一轮的裁定一致，只是这一步把引擎里最后一点残留
  的「知道能力长什么样」也去掉。

## Alternatives considered

- **只从公开面收掉，实现留在内部**：内部不发布，一个只有测试调用的导出实现就是死代码；而这两块的
  实现没有任何库内消费者——提炼要宿主触发，解析器要宿主的目录。留着只增加读代码时的辨认成本。否决。
- **保留解析器、只删提炼**：解析器确实有「免宿主双维护格式」的价值。但它维护的是宿主的磁盘格式，
  格式变了引擎要跟着发版，而引擎从这份格式里什么也读不出来——它不参与能力的存储、检索或执行。
  一个纯转手的校验器不值一个公开导出面。否决。
- **保留提炼、只删解析器**：提炼是「一轮事件 → 能力候选」的唯一出口，删了宿主就再也拿不到结晶。
  但这条能力本来就不产生任何持久状态，宿主自己读事件轨再调一次模型即可复现，而提示词是宿主的资产
  更合理。用户裁定整体退役。否决。
- **把两块挪到一个独立的子模块供宿主可选引用**：那只是把边界问题换个位置——引擎的仓库里仍然住着
  一个与记忆无关的模块，依赖图仍然要连过去。否决。

## Consequences

换到的是：引擎的公开面只剩记忆语义，宿主读文档时不必再辨认哪些导出与记忆无关；能力包之间那条违规
引用被消除（不是被豁免，是其中一方不存在了）；八个只为这两个方法服务的导出类型与常量离开公开面。

付出的是：宿主失去一个现成的能力文档解析器，要自己维护格式校验；失去「一轮事件 → 能力候选」的现成
提炼，要自己组织提示词与解析；这两件事对已经在做能力目录的宿主是纯增量工作。MCP 工具面少两个工具。

这一轮把「引擎不存能力记录」推进到「引擎不知道能力是什么」。上一轮留下这两块纯能力时的判断是它们
对宿主有价值——判断没错，错在把「对宿主有价值」当成了「该由记忆引擎导出」。
