# 决策档案: 巩固组的父话题 id 把自己的成员算进派生式

Status: implemented

## Problem

Dream 的 L2 融合给一个巩固组造一个 depth-1 父话题，父的 id 原先只由「场景 + 这一组的最早/最晚
时间界」派生。选时间界是为了可重放：同一组在下一次巩固里被再次提出时应当算出同一个父，而不是
又造一个。

但时间界**不能标识一个组**。宿主打时间戳粗到几轮共用一时（批量写入、恢复一批旧会话、测试种子），
两个成员完全不相交的组就会共用同一对时间界，于是算出同一个父 id。库里当时的处置是拒后到的那一组
——这个处置本身是对的：让两个组共用一个父，等于让第一组的摘要去管它从没说过的轮次，那是一条假记忆。

代价在被拒之后才显出来，而且是永久的：

- 被拒的那一组留在场景表面（depth-1），所以该场景的 depth-1 计数再也降不到压缩门限之下；
- 每一趟巩固都会重新列出它们、重新问一次模型「这几轮算不算同一件事」、再重新拒一次——
  一次真额度 LLM 调用换来的产出是零；
- 触发调度的是「场景攒够多少话题」，而这些压不掉的组自己就把计数顶在门限之上，所以这个循环
  由宿主每轮的收束持续供能，直到文件被裁掉那些轮为止。

一次四趟巩固的探针实测：第一趟 1 组落地 1 组被拒，第二到第四趟全部 0 落地、2 被拒，
模型调用一路涨到 4 次，表面话题数一动不动。

## Decision

父话题的派生式把**成员集合算进去**：场景、两个时间界、以及升序排列的成员 id。

于是「两个不相交的组撞同一个父」在结构上不可能发生，而原来选时间界所要的那个性质一条没丢——
成员升序后参与哈希，所以同一组无论模型以什么顺序点名都算出同一个父，重放仍然落在同一个地址上。

占用校验保留，但它现在守的是另一件事：同一成员集合被再提一次（已应用组的复读）仍然落在已被占用
的地址上，仍在写下第一条记录之前拒掉、无回滚。也就是说，守卫从「挡一个结构性的错」降级为
「挡一次重放」——这是它本来该干的活。

## Alternatives considered

- **只加止损，不改派生式**：某场景一趟里 0 落地而有被拒，就在域上下文里记下「这一阵别再为它提议」。
  省掉重复的模型调用，但那两组里输的一组永远压不掉，它的原文永久留在表面、场景永久高于门限。
  把缺陷留在盘上换一次安静，落选。
- **让后到的组挂进已存在的父**：两组都能"落地"，但父的摘要只描述了它自己那两组，第二组的轮次
  于是被一段没提过它们的话概括——这是一条假记忆，比压不掉更坏。落选。
- **给场景记一个「已试过的时间界」黑名单**：多一份要维护的磁盘状态，且只压住撞车不解决撞车，
  下一对共用时间界的组照样中招。落选。
- **让宿主负责给出唯一时间戳**：这是宿主做不到的事——一批恢复的旧轮次本来就可能共享一个时间，
  而引擎不能要求宿主的时钟精度才能正确巩固。落选。

## Consequences

换到的是：巩固对同批时间戳的宿主不再有条件性失忆，每趟巩固的模型调用花的都落在能推进的地方；
放弃的是「父 id 只由两个数派生」这一简洁性——它现在依赖成员集合，因此**一个组的成员若被别的组
先吞掉，这个组就不可能再算出原来的父**，而这正是想要的（它已经不该存在了）。

一条要如实说清的边界：派生式变了，磁盘上**已存在的**融合父 id 仍按旧式记录，且没有任何外部路径
会去重算它——子话题挂的是存下来的父链接，读路径不派生父 id——所以旧文件照开照读，`FormatVersion`
不动。代价是新旧两式之间没有任何区分标记：一个旧父与一个新父可能语义上指向同一批轮次，
但没人会把它们当成同一个，因为成员集合参与的推导只发生在「即将落地一个新组」的时候。

公开面不变，宿主不需要为这次改动改任何调用点。
