# 决策档案: L1 开一个只读面，写面仍归巩固流水线

Status: implemented

## Problem

场景节点这一层（记忆图里的节点与它们之间的共现边）全部由巩固流水线计算和维护：建边、按情绪加权的
指数遗忘、修剪与传播。宿主一个读入口都没有——这一层的模型类型从未越过门面，宿主既看不到某个场景
被算出了多重要的权重，也看不到它与哪些场景被判定为相关。

「L1 不开读接口」此前是一条既定决策，但它没有档案，只活在代码注释与仓库说明的散文里。它成立的前提是
这一层的值纯属引擎内部状态：宿主读它没有用，因为宿主无法参与计算，读出来也只是看一串自己改不了的浮点数。

前提在这一轮变了。宿主开始需要回答「这个 agent 的记忆里，哪些会话被判定为相关、关联有多强」——这是
它决定要不要把某段记忆带进上下文、要不要提示用户合并两个会话的依据。这个判断只有节点层能给出：场景
列表给的是「有哪些会话」，读一个场景给的是「这个会话聊了什么」，两者都不含关联强度。

## Decision

- **开一个只读方法，返回该域的全部场景节点**。节点的每一项都渲染成对外惯用的形态：id 是十六进制串，
  时间与权重原样透出。
- **返回顺序确定**（按 id 排）。底层索引是哈希表，不排序则同一个域两次调用返回顺序不同，宿主的输出
  会抖动，测试会偶发红。
- **不开任何写接口**。权重、边、节点与场景的对应关系全部仍归巩固流水线；宿主能读不能改。
- **节点上那组边的 id 照实渲染**，即使公开面没有任何调用能解析一条边。两个节点共享同一个边 id 就足以
  让宿主看出它们相连——这是这一层的结构信息唯一的出口，去掉它，只读面的信息量就等于零（节点剩下的
  独有字段只有三个权重，而「哪个场景对应哪些轮次」在场景列表与读场景里已经给过了）。

## Alternatives considered

- **节点与边一起返回**：视图自洽，宿主能看到边的类型、权重与上次衰减时间。代价是要新增一个边的
  批量读取原语、把边 id 的派生规则从函数体里提出来导出（与节点 id 的既有导出助手对称）、再导出一个
  边类型的枚举——公开面多一个类型、多一组常量，换来的信息是「这条共现边有多强」。用户裁定只要节点。
  否决，但记在这里：若将来宿主要按关联强度排序，边权重是必需的，那时再加。
- **只返回节点、且去掉边 id**：面最小。但那样宿主拿到的是一堆孤立的权重，无法判断任何两个场景是否
  相关——而这正是开这个读面的理由。否决。
- **把边 id 折成一个派生值**（比如「该场景有几条共现边」）：不给悬空引用。但计数是引擎派生的展示
  字段，它的死因与话题上那个派生标题一样——一旦派生规则要改，磁盘上的旧值就成了需要迁移的负担；
  而且计数回答不了「和谁相连」。否决。
- **连写面一起开**（宿主可以直接改权重）：宿主改的值会在下一次巩固时被重算覆盖，一个会被静默推翻的
  写接口比没有接口更糟。否决。
- **按场景取单个节点而不列举全域**：面更小，但宿主要的是「哪些会话彼此相关」，这是一个全域问题，
  按场景逐个取要 N 次调用且仍然拼不出关联图。否决。

## Consequences

换到的是：宿主第一次能读到关联强度，据此决定上下文取舍；这一层的模型类型有了对外的渲染形态，之后
若要加边视图，DTO 的形状已经在那里。

付出的是：公开面多一个方法与一个导出类型；边 id 是宿主无法解析的悬空引用，文档必须讲清它的唯一用法
是「比对两个节点是否共享」，否则宿主会去找那个不存在的解析入口；「L1 无读 API」这条旧决策没有档案，
所以本档案无处挂取代标记，它推翻的是散落在代码注释与仓库说明里的两句话——那两处必须在本轮同批改写，
否则文档与档案互相矛盾。

写面不变，所以这一层的一致性契约没有被触动：权重与边仍然只有一个写入方。
