# 决策档案: 话题名是宿主授权字段，不是引擎派生的展示字段

Status: implemented

## Problem

一轮对话沉淀成一个话题，话题身上能被读出来的标识只有一串融合关键词。宿主没有办法给某一轮起一个
人能认的名字——「决定把 L5 让给计划树的那一轮」这种指称在库里无处安放，宿主只能自己另建一张
话题 id 到显示名的映射表，而那张表不参与库的任何一致性保证：话题被合并、被删除、被巩固流水线压缩
成父话题之后，宿主表里的条目就成了孤儿，且没有任何一处会报错。

这一层曾经有过一个标题字段，随读它的检索子系统一起退役了——那次退役的理由是它是引擎派生的展示
字段：引擎从原文里截一段填进去，没有独立的写入方，读它的子系统一走，它就只剩写入成本。缓存层的
注释至今这样记着这件事。

现在要加回一个名字字段，所以必须先把两者分清楚，否则这一轮看起来像是在撤销一次正确的退役。

## Decision

- **话题带一个名字，归宿主授权**：只有宿主能写，引擎不派生、不猜测、不从原文里截。它与那个已退役的
  标题的差别不在形状而在写入方——那个是引擎算出来的展示值，这个是宿主给的指称。
- **创建时一律无名**。轮次话题与巩固流水线折出的融合话题都不带名字：融合话题是一个新的可命名对象，
  与被它吞掉的子话题不是同一个东西，从子话题折一个名字出来既越权（那个名字是宿主授权给某一轮的）
  又把它变回派生字段。无名是一个合法且可辨识的状态，磁盘上零成本。
- **改名拒绝空名**，与场景改名对称。清空一个名字没有用例，而「空」要留给「还没命名」。
- **名字在读路径上到处可见**：读一个场景返回的话题列表、以及整场转录的读取结果都带上它。只在写路径
  存在、读路径缺席的字段等于不存在。
- **巩固与合并不动名字**。压缩把子话题下沉时整体重写记录，名字自然保留；合并场景改的是话题的场景
  归属，同样整体重写。两处都不需要为名字写任何特殊逻辑，这也是「字段归宿主、引擎不派生」的直接收益。

## Alternatives considered

- **让引擎在沉淀那一轮时从首条用户原文截一段做种子名**：宿主开箱就有个能看的名字。但这正是旧标题的
  死因——派生规则一改，磁盘上的旧值就成了要迁移的负担；而且截出来的名字宿主要改，改完又被下一次
  派生覆盖，除非再加一条「宿主改过就不再派生」的标记。为一个展示值引入一个状态位，否决。
- **名字放在库外，由宿主自己维护映射表**：库零改动。但这就是现状，而现状的问题（合并、删除、压缩
  之后映射成孤儿且无人报错）正是本档案要解决的。否决。
- **复用融合关键词字段当名字**：不新增字段。关键词是引擎在沉淀时蒸馏出来的、多个词的集合，语义与
  「一个指称」不同；覆盖它等于让宿主的写入与引擎的写入抢同一个字段。否决。
- **名字挂在场景上而不是话题上**：场景已经能改名了。但宿主要指称的粒度是「哪一轮」，一个场景下有
  多轮；挂在场景上回答不了这个问题。否决。
- **允许清空名字**（把改名接口的空值读成「撤销命名」）：多一个状态迁移，而没有用例——宿主不想要
  名字时不会去撤，它一开始就不会起。与场景改名的既有规则保持一致更重要。否决。

## Consequences

换到的是：宿主的指称有了库内的归宿，跟着话题一起被合并、删除与压缩处理，不需要第二张表；名字只有
一个写入方，所以不存在「派生值覆盖宿主输入」这类需要状态位去防的冲突。

付出的是：话题记录多一个字段，磁盘格式版本随之抬升（与身份字段同一轮）；缓存层要承载它，而缓存的
重建与读回是两条不同的路径——任何一条漏了这个字段，同一个话题会在两条路径上给出不同答案且无一处
报错，这是本轮最容易埋进去的静默缺陷，必须有守门测试；改名写完记录还必须同步缓存，否则新名字在
下一次巩固重建索引之前对读路径不可见。

缓存层那条「派生展示字段已退役」的注释必须改写。它记的是真事，但它描述的对象与本轮加的字段不是一类
东西，留着会让下一个读者以为这一轮撤销了一次正确的退役。
