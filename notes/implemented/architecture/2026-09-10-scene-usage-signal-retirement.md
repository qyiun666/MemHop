# 决策档案: 场景的读侧信号退役（Dream 的 usage-feedback 阶段一并删除）

Status: implemented

## Problem

L2 场景记录上有三个字段是给「谁读过这个场景」记账的：`HitCount`、`LastHitAt`、`TopicCount`。

前两个的唯一消费者是 Dream 的 usage-feedback 阶段：距上次读超过 1 小时、或从未被读，就把该
场景 L1 节点的 `Importance` 减 0.05，否则加 0.05。这笔账买不到东西——节点移除阈值 0.05、
衰减率 λ=0.01/小时、新建初值 1.0，意味着一个节点自然落穿要 300 小时量级，而一次巩固里加或减
的那一档只是 0–1 量程上 5% 的抖动，**它不改变「哪个场景节点会死」的答案**。它不决定合并
（融合由 LLM 提案、按 depth-1 话题数触发），也不决定任何读路径。

代价却挂在最热的读路径上：每次 `Search` 都要为这两个计数器写场景记录，而 `Search` 的契约
本来就是「读一个场景 = 开一轮」。

第三个字段更直接：`TopicCount` **从来没落过盘**——`NewSceneSlot` 不置它，`OpenSceneTurn`
回写的是刚读到的那条记录，所以磁盘上恒为 0；三处赋值全是读后现算的内存值，其中
`CollectAllScenesL2` 为了填它要全扫一遍域内话题。一个恒零的持久化字段加一次为算它而做的
全扫，两头都是纯支出。

## Decision

- 三个字段同时从 `core.SceneSlot` 与 `api.SceneSlot` 删除。场景记录在读取路径上只剩
  `TurnSeq` 一个计数器，`OpenSceneTurn` 也只剩推进它这一件事（连带删掉为时间戳而留的形参）。
- `usage_feedback` 阶段整体退役：判定函数、它的 1 小时窗、以及 `DreamStage` 名称词表里的这一项。
  `index_rebuild` 的阶段上报保留在原位置，阶段链变为 L2Meta 重建 → L1 各阶段 → 装回缓存 → L0 蒸馏。
- L1 节点重要性此后只有两个来源：同步新建时的 `1.0` 与指数衰减（含按情绪调制的速率）。
- `TopicCount` 的派生填充随字段一起删除；**`SceneContext.TopicCount` 保留**——它说的是本次读
  返回了几条条目，与场景记录上的「depth-1 根数」不是同一件事。

## Alternatives considered

- **用 L4 最近一条内容的时间近似 `LastHitAt`**——落选：L4 有 7 天保留窗，超窗之后近似恒为零，
  等于把所有老场景永久判冷，而这恰恰是这个反馈原本想做反的那件事。
- **用 L1 节点自己的 `UpdatedAt` / `LastDecayAt` 当新近度**——落选：这两个时间戳由 Dream 盖，
  记录的是巩固节奏而不是宿主行为，换过去等于用自己喂自己的循环冒充外部信号。
- **只删 core 字段、`api` 上保留**——落选：门面那个字段是 core 的镜像映射，留一个恒零的公开
  字段比删掉它更坏（宿主会以为它有值）。
- **保留字段、把阶段改成「只统计不写回」**——落选：不写回的统计在库内没有读者，剩下的只有
  热路径上那次写。
- **顺带把 `TurnSeq` 也换成「该场景的话题数」**（同一轮讨论里提出的自增主键方向）——落选，
  且落选理由比上面几条硬：话题数会因 Dream 下沉子树和 `DeleteTopic` 而**单调回退**，轮次 id
  由它派生就会与别的轮撞车，撞在内容记录的派生键上就是把另一轮的原文原地覆写掉。`TurnSeq`
  是本仓唯一能同时满足「发号时文本还不存在」与「永不回退」的发号源，属于 load-bearing 字段。

## Consequences

- **换来**：`Search` 在场景记录上写的字段从一个变零个额外项（只剩轮次计数）；场景记录不再携带
  引擎自己不消费的统计；Dream 少一个阶段；`api.SceneSlot` 收窄为 `{scene_id, scene_name, l3_id}`。
- **放弃**：全仓唯一的**读侧**信号。此后「被读过」与「最近有写入」在引擎里不可分辨，L1 节点的
  存活完全由时间决定。若将来要做「常被访问的场景活得更久」，判断标准写在这里：读侧信号必须
  有一个非衰减性的消费者，而不是只给衰减自己加一档抖动。
- **对宿主**：breaking——`api.SceneSlot` 三个公开字段消失（随 v1.6.3 一并生效，跟版由宿主侧处理）。
- **验证**：`TestOpenSceneTurnAdvancesTurnSeq` 与 `TestSearchIsReadOnlyAndCallsNoLLM` 改钉
  `TurnSeq`；`TestSceneContextOpensNoTurn` 把「恢复读不开轮次」这条契约搬到能读到记录的地方，
  并额外断言下一轮拿到的正是紧邻的那个 id（跳过一轮会让那一轮永远没有主人）。
- **同批完成**（共用这次版本上抬，不构成独立决定）：空出的 L5 号位交给计划树，两个还含层号的
  id 命名空间去层号（`l1:`→`scene-node:`、`l4:`→`content:`），归档的归属字段由 `context_id`
  改名为它一直存放的东西 `topic_id`；格式版本 `0x000F`，`0x000E` 及更早的 `.meh` 在 Open 拒绝、
  不迁移——宿主磁盘上的记忆文件需重建。
