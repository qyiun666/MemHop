# 决策档案: 计划步骤按轮内序号寻址，树一笔一笔写

Status: implemented

## Problem

`PlanSet` 的一次声明形态要求宿主每轮把整棵计划重述一遍。宿主手上真正发生的事是「按计划走一步、
把它做完、必要时把某一步拆开」，于是绝大多数轮次里，重述的内容与上一轮逐字相同——每次改一步都要
把没变的那些步骤重新发一遍，而 LLM 重写整棵树本身就是一次可能改错别的地方的机会。

同时，点号路径 `"1.2.1"` 承担了三个角色：宿主的步骤编号、磁盘上的记录身份、L4 事件的归因列。
它的代价此前已记在 `2026-09-09-turn-topic-id-is-the-only-join-key.md` 的邻档里，这一轮又添两条：
一条路径打错会顺手长出一棵没人计划过的树（缺失的祖先段被自动建成 pending），而「这一步的父是谁」
这件事在库里能靠路径推、也能靠 `ParentID` 列推，两样必须永远一致，而它们由同一次写入派生，
没有独立的信息量。

## Decision

一棵树仍属于开出它的那一轮（归属粒度不变），但写面与寻址都换：

- **逐节点写**：`PlanCreate(topicID, title) → seq`、`PlanNodeAdd(topicID, parentSeq, title) → seq`、
  `PlanNodeUpdate(topicID, step) error`。改一步只发一次调用。公开面 25 → 27。
- **一步由该轮内的整数序号寻址**：`Seq` 由库顺序发号（从 1 起），`ParentSeq` 指父、0 即根；
  记录 id 仍是从这两者派生的哈希，`NodePath` 字符串从节点记录与事件记录上一起消失。
- **序号是地址不是 id**：它以一个普通整数越过门面，与 `NodePath` 一样属于「轮内的位置」，
  `TestPublicSignaturesCarryNoNumericIds` 的 hex 契约不被触动。
- **一步只能被创建出来**：`AppendArchive` 与任何读路径都不建节点；`PlanNodeAdd` 的父序号不在树上
  即 `ErrNotFound`，不补链。
- **状态三态**：`in_progress` / `done` / `failed`，且 `in_progress` 占存储值 0——新建的那一步
  本来就在做，所以创建口不要求宿主给状态，`pending` 随之一并退役。
- **一步的读值范围是它的子树**，闭包沿 `ParentSeq` 求，取代 `repo.NodePathUnder` 的前缀匹配。
- 仍**不开节点删除口**，仍**不把「没提到这一步」读成「这一步被撤掉了」**：这两条与
  `2026-09-10-plan-tree-declared-per-turn.md` 的裁定一致，本轮没有推翻它们。
- 格式版本 `0x0010 → 0x0011`，旧文件拒开、无迁移。

## Alternatives considered

- **保留一次声明，只在文档里教宿主「少重述一点」**：省不掉调用，因为写面本身就是整棵语义——
  宿主没有「只交这一步」的合法表达。
- **序号对外也包成 16 位 hex**（把 `Seq` 叫成 `NodeID` 并渲染）：守住「一切对外 id 皆 hex」的字面，
  代价是宿主每轮要把 `0000000000000007` 这样的串在 LLM 的 prompt 与解析之间搬来搬去，而它回答的
  问题只是「这是第几步」。宿主侧的步骤编号本来就是自然数。
- **`Id uint8` 自增**：255 步的上限会撞到一棵长计划树，而且域内所有 id 都是 `uint64`/hex，
  单独把一层的宽度缩到 8 位买不到任何东西。
- **保留 `NodePath` 只把写面拆细**：两条路径共存 = 同一功能两个实现，正是退役 `SyncPlanTree` 时
  用过的判据；且前缀匹配与父链接两种「谁是我父」会各自演化。
- **树的归属换成 L2 场景（一个会话一棵树，跨轮演进）**：与
  `2026-09-09-turn-topic-id-is-the-only-join-key.md` 正面冲突，代价见该档；本轮用户未要求换归属，
  只要求换寻址与写面。
- **序号由场景记录上的计数器持久化**（仿 `turn_seq`）：话题 id 反推不出场景 id（哈希不可逆），
  要新增一条话题→高水位的记录或索引，而这轮真正被消掉的是复杂度不是持久化字段。改为接受
  「任何一次移除都腾出一个序号」这个上限（清空一棵树即这一轮从 1 重新开始），并在发号处
  以 `ponytail:` 标注升级路径。

## Consequences

换到的是：宿主的热路径从「每轮交整棵」变回「每轮交这一步」，且调用数与它真实的动作数一致；
节点不再可能被一次打错的路径批量造出来；一步的父子关系在磁盘上只有一个来源（`ParentSeq`）。

付出的是：公开面从 25 涨回 27，这是本版本内的首次扩张（此前每一轮都在收敛），需要在下一条 tag
前重新过一遍「每个新方法是否挣得到自己的饭钱」；序号是跨轮不稳定的人造编号（第 3 轮的 1 与第 4 轮
的 1 无关），所以宿主必须自己记「这一步的序号」，不能像点号路径那样由自己按规划重算；`Seq`
复用是明码标价的**未闭合**缺口，不当它不存在——共用保留窗兜不住它：节点按自己的 `UpdatedAt`
老化，事件按自己的 `CreatedAt` 老化，而「事件活过自己那棵树」是本仓一条测试钉住的现状，于是一棵
被扫空的旧轮次再被写入时，新步骤可能顶着一个仍有事件指着它的序号。对宿主的边界写在门面方法上：
回到一个老于保留窗的轮次时，手里的旧序号按新步骤的地址对待，不当作同一步。

L4 事件的归因列改名 `node_seq`，MCP 的两个参数随之改名，工具数仍 24、计划写面仍不上工具面。
