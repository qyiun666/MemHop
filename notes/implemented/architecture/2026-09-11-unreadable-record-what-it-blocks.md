# 决策档案: 一条读不回的记录挡住什么

Status: implemented

## Problem

一个 `.meh` 文件里可能有一条记录读不回来：帧在索引里、payload 解不开，或者底层读不动。
每一处扫描、每一个入口都必须回答同一个问题——**跳过它，还是停下来**。答错的代价不对称：
把「读不回」答成「没有」，会让一次瞬时读失败去删掉或覆写一条记忆（本仓出过三起：画像被
空值覆盖、L1 节点被新建的顶掉、级联删掉一半）；反过来处处都停，则一条坏记录能让整个文件
不可用。

## Decision

分界画在**这次读的后果**上，不画在错误类型上，共三档：

- **决定下一次的写的枚举**必须整个读得回来——删谁、覆写谁、还是要不要新建哪一条（保留窗
  清扫、话题与整图级联、L1 节点同步与重建、按域改写锚点、图导入批次对整池标签/标题/边键
  的播种），并且排在任何墓碑之前——被拒的一次才真的什么都没做。撤销自己刚写
  的记录按那个 id 定点做，它不需要枚举。
- **重建一份镜像或缓存**的扫描跳过它：一条记录在镜像里缺席，与它被保留窗裁掉是同一个形状，
  下一次重建自然对齐。
- **只作为一次算法输入**的那份读（衰减遍历边、蒸馏取样、交给模型的列举）同样跳过：代价是
  这一轮少算它，盘上不会多出说不清的东西。

入口层面：**损坏只挡住会 acting on 错答案的那个动作，不挡住打开文件。** 一条解不出名字的
租户注册记录仍然占着一个域，所以建新域被拒（`SubAgent` 给新名字时），而 `Open`、主域与所有
已解析出的名字照常工作。修复手段是 `CompactTo`——一次由宿主显式要求的、以幸存记录重写文件
的动作，不是引擎在读路径上顺手做的自愈。

## Alternatives considered

- **处处严格**（任何扫描遇到读不回就报错）：被否。一条坏记录会让闲置清扫、巩固流水线、
  域上下文重建全部停摆，等于用一条记录换整个文件；而这三类扫描少算一条并不留下不一致状态。
- **有损即拒绝 `Open`**：被否。损坏通常只落在一个租户的键上，拒绝打开会让健康的主域和其余
  租户一起失去访问，而宿主最需要的恰恰是打开以后把它能救的东西搬走。
- **读路径上就地丢弃坏记录**（自我修复）：被否。一次瞬时 IO 失败会变成一次不可逆的删除；
  修复只作为宿主显式发起的 `Compact` 存在。
- **保留原状**（`bool` 返回值、把读失败改写成 `ErrNotFound`）：被否，这就是本档要解决的三起
  缺陷的成因；错误码在数据层就已分得清，往上压平等于把判断交给最不知道内情的调用方。

## Consequences

- 换来的：数据层之外不再需要猜「短了一截的清单是真没有还是坏了」；被拒的操作一律零留痕。
- 付出的：几个原语从 `bool` 改成带 error 的返回（`MergeScenesL2`、`DeleteGraphL3`、两个话题
  写入口），调用点必须带出因而不是自己编一句；同一层里两份扫描各一套（严格/容错），选错
  一份的风险由命名与本仓 `internal/agent.md` 的错误判定纪律条目承担。
- 未解决的：一条坏记录仍然会让它所在域的相应操作长期被拒，直到宿主跑一次 `Compact`。引擎
  不提供「坏记录清单」这类读面。
- 判据外扩到公共池的代价：图槽、节点、边同住文件级公共池，导入批次按整池枚举播种，于是池里
  任意一条坏节点会拒掉**所有 agent** 的 `ImportL3`，而 `GetL3`/`ListL3`/`QueryL3Nodes` 照常给
  答案。换来的是同一标签下不再铸出第二张图，也没有按位置式 id 覆写一条读不回的节点还算成新增。
