# 决策档案: 四个调参旋钮统一成「留 0 就是没填」

Status: implemented

## Problem

`MemHopDefaults` 四个字段各自解释自己的零值：两个把 0 当「关掉」，一个把 0 当「不跳过而且让模型按 0 去合」，
只有保留窗口把 0（及负数）当「取库默认」。同一份类型里三种读法并存，而 `LlmConfig` 的两个预算早就是
「留 0 = 取默认」这一种。后果不是没效果而是丢细节：拿最短示例抄下来的宿主传的是零值，于是自动巩固被关掉，
而它哪次自己调 `Dream`，提示词就照字面写着「把这个场景的话题数压向 0 或以下」。

## Decision

一处归一化，落在宿主的结构体变成引擎配置的那一刻（`Open`/`OpenDB`）：`0` 一律读成「没填」，由
`DefaultMemHopDefaults` 顶上；「关掉这一项」改用显式负数。压缩门限的负数折成 0——0 才是「不设目标」那个
真实取值，负数不该出现在交给模型的提示词里。保留窗口没有「永不过期」的写法，0 与负数都取默认窗口。
六个读取点不改，测试面钉三件事：全零表 == 库默认、填过的字段不被改写、负数各按自己的关掉读法。

## Alternatives considered

- **只在整张表全零时回落**：改动最小，但「一半默认一半关掉」的歧义正是问题本身——`{DreamCompressMinTopics: 0}`
  配其它三项有值，仍会渲染出「压向 0」。
- **不改语义，只把警告从字段注释抬到 `Open` 的签名与指南首行**：靠宿主自觉；「照最短示例抄」这条路依然掉坑。
- **保留 0=关掉以维持向后兼容**：这三条读法尚未随任何 tag 发布，兼容的是本仓自己的测试夹具与一个宿主脚手架
  里显式写的 -1（新语义下 -1 仍然是关掉，不需要改）。
- **给保留窗口加「永不过期」**：保留是文件大小的唯一上界，开了这个口就没有上界。

## Consequences

换到的是：`api.Open(path, llm, api.MemHopDefaults{}, profile)` 与传 `DefaultMemHopDefaults` 行为一致，
调一个字段不必先复制整张表；配置类型内部只剩一种读法，与 `LlmConfig` 对齐。

付出的是：确实把 0 当「关掉」用的宿主会拿到默认值——方向是更保守（开始巩固），不是更丢数据。三仓 e2e 复跑
14 条仍全过，而它正是拿零值表在跑：改前那次 `Dream` 里有一次巩固调用、场景表面 4 个话题（其中一个是融合父），
改后巩固按门限跳过、零次该调用、表面 3 个话题、关键词调用 6→5。旧行为不是「更会用模型」而是「被零值逼着
没有门限地合」，这条差异即本档案要留下的判据。
