### 2.2 LOCOMO 基准对比

**注意**: 各竞品报告的是 **LLM-as-Judge accuracy**（答案正确率），MemHop 报告的是 **Recall@K**（检索召回率），不是同一指标，不能直接比较。以下数据来源于各竞品公开发表的论文和基准报告。

| 系统 | 指标 | LOCOMO | LongMemEval |
|------|------|:------:|:-----------:|
| Mem0 Platform | accuracy | **92.5%** | 94.4% |
| Mem0 OSS | accuracy | 67.13% | 49.0% |
| Letta (MemGPT) | accuracy | 83.2% | - |
| Zep/Graphiti | accuracy | - | 63.8% |
| agentmemory | recall@5 | - | 95.2% |
| **MemHop (BGE-M3, smoke)** | **recall@5** | **1.000** (smoke) | - |
| MemHop (e5-small, full) | recall@5 | 0.282 | - |
| MemHop (e5-small, full) | nDCG@10 | 0.235 | - |

**理解**：
- **accuracy** (Mem0/Letta) = LLM 基于检索结果生成答案，评判答案正确率。隐含了 LLM 的推理能力。
- **recall@K** (MemHop/agentmemory) = 检索结果中是否包含相关文档。纯检索能力。
- MemHop smoke 测试仅有 2 个会话，检索空间小，Recall@5=1.00 属于预期结果。
- MemHop 旧版全量 LOCOMO (e5-small) 显示 recall@5=0.282。使用 BGE-M3 后预期会提升。

## 三、结论

1. **检索准确率**：Smoke 测试 Recall@5=1.00，全量 LOCOMO 需 BGE-M3 模型重新跑（旧版 e5-small 为 0.282）。
2. **功能覆盖**：MemHop 的 6 层认知架构在功能完整度上领先所有竞品（唯一支持超图推理、DSL 查询、社区发现、程序记忆、通路权重）。
3. **部署优势**：单文件 `.meh` + 零外部依赖，是唯一可嵌入式部署的记忆方案。
4. **性能瓶颈**：当前主要延迟在 BGE-M3 ONNX gRPC 向量编码（占总时间的 90%+），MemHop 自身检索逻辑在微秒级。
