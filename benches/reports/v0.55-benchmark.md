## GTE 768维真实模型测试

使用本地 `models/gte-multilingual-base/`（768 维，float16）启动 meowvec gRPC 服务，Apple MPS 加速，运行 `cargo bench --bench retrieval_benchmark`。

### 环境

- 模型：`models/gte-multilingual-base/`（Alibaba-NLP GTE 多语言模型）
- 维度：768
- 设备：Apple MPS（Metal Performance Shaders）
- 模型加载时间：9.66s
- 检索权重：BM25=0.45，Vector=0.55
- `rerank_max_candidates`：20
- rerank 超时：5s
- rerank 实现：bi-encoder 余弦相似度（非 cross-encoder）
- fixture：`benches/fixtures/locomo_smoke.json`（10 个问题）

### 命令

```bash
# 终端 1：启动模型服务
python3 examples/meowvec_server.py --port 27110 --model-path models/gte-multilingual-base/ --dimension 768

# 终端 2：运行基准测试
MEMHOP_BENCH_ENCODER_ADDR=http://127.0.0.1:27110 BENCH_VECTOR_DIM=768 \
    cargo bench --bench retrieval_benchmark
```

### 结果

| 指标 | 结果 |
|------|------|
| Recall@5 | **1.00** |
| nDCG@5 | **1.00** |
| P99 延迟 | **462.5 ms** |
| max 延迟 | 852.5 ms |
| search_memory throughput | [859.8 ms - 1.4 s] / query |

### 分析

1. **Recall@5 / nDCG@5 = 1.00**：smoke 数据集规模小（10 个问题），GTE 768维在该数据上区分度极高。需在大规模数据集（LongMemEval/LoCoMo full）上验证实际效果。

2. **P99 延迟 462.5ms（目标 <200ms）**：超标 2.3 倍。原因：
   - GTE 768维模型推理比 e5-small 384维重一倍（模型参数 318M vs 118M）
   - 当前 rerank 使用同一 bi-encoder 做 query-doc 余弦相似度，需额外编码一次文档
   - Apple MPS 推理性能有限，专用 GPU 或量化后应能显著降低
   - 每次 search 包含：BM25检索 + 向量编码 + IVF查询 + rerank编码+相似度，全链路累计

3. **优化方向**：
   - 生产环境使用专用 cross-encoder（bge-reranker-v2-m3）替代 bi-encoder rerank，减少编码次数
   - 启用向量量化（f16 推理），降低内存带宽压力
   - 限制 rerank 候选数至 top-10（当前 20）
   - 使用 GPU 服务器部署模型（而非 Apple MPS）
