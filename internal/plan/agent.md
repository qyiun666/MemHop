# internal/plan — L5 计划树小方法

## 职责

- 状态面：`PlanStatus` 字符串面与 `StatusToU8`/`StatusToString`/`IsTerminalStatus`。
- 两个入参形状：`NodeSpec`（要创建的一步：归属话题 + 父序号 + 标题）与 `Step`
  （要重述的一步：归属话题 + 序号 + 状态 + 标题 + 摘要）。
- 写步：`CreateNode`（发号并落一条节点记录）、`UpdateNode`（状态 + 节点自身字段）、
  `UpdateNodeSummaryLocked`（只填 Summary，绝不动 Status）。
- 树构建：`BuildTree`/`Forest`/`ToNodeView`/`CountForest`，以及回填 `RollupTree`。
- 本包只写计划节点记录：一棵树归属一个话题键，键的解析不在这里。

## 契约

- 所有写步要求调用方持 `ac.Mu`；缓存同步经 `ac.Plans`（无自带锁）。
- `PlanStatus`/`PlanTree`/`Step`/`PlanNodeView` 的唯一定义处。
- 一步由 (话题, `Seq`) 说清：`Seq` 是该话题内从 1 起顺序发号的序号，`ParentSeq` 指
  它挂在谁下面、0 即根；记录 id 由 `HashPlanNode(topicID, seq)` 派生，所以同一个序号
  在两个话题下是两个互不相干的节点。发号在 `ac.Plans`，本包与调用方都不自备序号。
- **一个步骤只能由 `CreateNode` 带出来**：父序号不在树上就拒，绝不补链。
- `CreateNode` 第一件事是查父序号在不在树上，落记录前还要读一次那个地址：发号读的是缓存，
  而缓存只收解得开的记录，解不开的那条仍占着自己的地址，所以除「不存在」以外的任何一次读失败
  都不写。`UpdateNode` 第一件事是 `StatusToU8`——解析不出就返回，节点还没被读过。被拒的写
  零留痕，调用方不必拿现树去 diff 才知道哪条落了自己。

## 陷阱

- 序号恒为「活节点最大值 + 1」，父必须在树已存在，而重述既不改 `Seq` 也不改
  `ParentSeq`——于是 `ParentSeq < Seq` 是写入面维持的不变量，一棵树上造不出环，
  求子树闭包因此不需要 visited 集。
- `Status` 是节点里唯一需要解读的裸 uint8，词表只有一张（`statusNames`，双向都读
  它）：未定义的存储值在 `StatusToString` 报错而不是回落某个能叫出名字的状态——回落
  会把「引擎叫不出名字的一步」显示成它从没到达过的状态。
- 状态面只有 `in_progress`/`done`/`failed`，且 `in_progress` 就是 0：新建的一步零值
  即合法，创建口因此不要求调用方先声明状态。同义的第二词与「已计划未开始」都不在词表
  里——留两个库分辨不出差别的词，等于让写入方掷硬币。**收词表不是改个常量**：被腾出
  的存储值会在存量节点记录里走进上面那条报错路径，所以它要连带处理已经写出去的文件。
- `RollupTree` 只在三个条件同时成立时回填：父节点自己 Done、它的 Summary 为空、每个
  直接子都到了终态。少最后一条就是半成品拼起来读起来像结论——「做了三件事；两件」读
  起来与一份完整摘要没有区别，而父节点上没有任何东西说明第三件当时还开着。它绝不改
  Status。
- 节点排序只看 `Seq`，也就是创建顺序；父记录缺失的节点提升为根而不是丢弃。
- 序号没有前缀形状可匹配，树的形状只由 `ParentSeq` 求闭包得出；除节点自身的
  `ParentSeq` 之外，本包不维护第二份指向某个步骤的引用。
