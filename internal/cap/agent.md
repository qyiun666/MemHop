# internal/cap — 能力层契约（模块级 agent 上下文）

本目录下的每个子包是一个功能：身份中立组件，只声明自己需要的接口与参数。
修改任何能力包前先读本文件；改完同步该包自己的注释。

## 分工（一功能一包）

- `engram/`：L1 场景超图的共现建边（Jaccard）与遗忘衰减
  （`BuildHyperedges`/`DecayNetwork`/`RebuildFromL2`）。一条已存在的边的权重只在
  某一端点**名下的轮次清单变了**（少一轮与多一轮同算）时才上升：`touched` 说的是这个，不是
  「关键词变了」——同一批轮次被再蒸馏一次，清单没变而重算出的相似度还是建边时那个值，按它
  抬权等于每轮把衰减抹平。节点这一侧没有独立的衰减钟字段：衰减读节点上的 `UpdatedAt`，并在算完之后
  把同一格回戳到本趟时刻。读与回戳落在同一步，只有在**衰减可复合**时不打架——两趟各一小时必须落在
  与一趟两小时同一个重要性上（`TestNodeDecayComposesAcrossPasses`：回戳停在本次时刻、两趟等于一趟、
  区间里这口钟被推进过的节点不为整段买单）。
- `llmops/`：三类 LLM 调用点的 prompt 契约、输出解析与自愈重试预算
  （`ExtractKeywords`/`Consolidate`/`Distill`）；传输经注入的 `Chat` 接口。
- `profile/`：L0 画像的紧凑摘要（`Brief`）、蒸馏样本与排名（`Samples`）、蒸馏结果
  写回（`MergeDistill`）。样本的关键词按节点名下的话题逐个读回来，读不回的那一个让这一行
  **掉出样本集**，而不是以空关键词入列：prompt 要模型从每行带的词推情感与人格，一行什么都不带
  只是让它从没有证据的地方编一个，而条数照旧算进那 200 条。`Brief` 反过来对全零的情感状态
  **不渲染**：那三个 0 在本仓标度上是「极负面 / 平静 / 顺从」的合法读数，可它与「从没蒸馏过」的
  画像在形状上分不出来，而这份摘要随每一次调用走——两头都不说，好过把一个没人测过的读数塞进
  每一次 prompt。
- `knowledge/`：L3 导入节点的字段合并策略（`MergeFields`/`OverwriteFields`）。

## 纪律

1. **身份中立、依赖注入**：只接收数据与注入的原语（engine / index / `Chat`）；
   禁止 new 依赖、禁止 import `internal` 根（会形成反向依赖环）。
2. **依赖方向**：`cap -> {common, repo, repo/core, repo/index}` 单向；能力包之间
   互不 import，需要协作时回到组装根编排。
3. **窄接口**：只声明自己需要的小接口（≤3 方法），如 `llmops.Chat`——注入方以
   结构化鸭子类型满足它，不需要显式适配。
4. **不认识编排，预算各归各包**：本层不因触发阈值而运行、不决定一次调用改完的记录
   归谁镜像、也不负责失败后的回滚——这些都是调用方的事。收到的东西并不统一：
   `llmops` 收渲染好的文本，`profile`/`engram`/`knowledge` 收注入的 engine/index
   原语，按各自算法需要读自己那一层的邻域；裁剪上限同样住在各自包里（`profile` 的
   样本数与每样本关键词数、`llmops` 的重试阶梯）。

5. **读失败不当成「已消失」**：本层凡以一次读的结果决定一条记录的去留（L1 衰减的
   两处级联、depth-3 的保留规则、共现建边对一条已存在的边怎么处置、建边读一个节点名下
   话题的关键词），一律按错误码分道
   ——现下的巩固最深只写到 2，depth≥3 的记录只可能出自成员互斥修好之前那批 0x0012 文件
   （同一轮会被沉两次），更早的版本根本打不开。分道即
   `ErrNotFound` 才是没了，`ErrIO` / `ErrDeserialization` 上抛、让调用方停下这一轮。
   把后者改写成「没了」，后果分三种：那条记录不会再自己长回来（衰减级联）；它被
   一份新建的顶掉、连时钟一起复位（建边把一张已衰减的边复原成满权重）；或者这个节点被量到的
   词集悄悄变小、相似度落到阈值下、**这条边根本不建**——衰减是单向的，抬权又要一端的证据本轮
   真的动过，所以它也不会自己回来。三种都比少做
   一轮难查。
   反过来，一次**查得清的「不在」**是要处理的现状，不是「不动」：共现边的成员按
   「本域还持有这个节点吗」过滤——本轮刚删的那几个与更早被别处摘掉的那个走同一条——
   剩下不足 `MinEdgeNodes` 就连边一起删。指着一条不存在节点的边不是共现关系，
   却照旧占着权重与衰减时钟。
   同一判据也管**整集的枚举**：本层三处按域列举 L1 节点（建边、陈旧重建、衰减）都走严格那份，
   读不回一个节点就带着它自己那一档码停下这一轮——衰减是唯一会移除节点的通道，被这次扫描
   跳过的节点永远不会淡出；建边按这份集合决定谁与谁相关，少一个节点不是少一条边。
   例外只有 `profile.Samples`：它排在那三处之后、同一次持锁之内，坏节点早就让本轮停下了，
   在这里再拒一次只是同一份拒绝的第二份副本。

6. **模型的答复分「答得少」与「没答到契约上」**：一次调用契约里的整块缺失（`distill`
   的 `emotion`/`mbti` 两块之一没有）不是「情绪很平」，而是没有答案——把解码出的零值交回，
   调用方就会拿它盖掉库里已经蒸馏的那半，一律 `ErrLLM`。答到了契约上但某一轴给 0，才是
   真的「这一轴没强度」（prompt 自己写着 magnitude = strength）：该轴取 `X`，四轴全 0 就
   一个类型词都不给——一份没有证据的回答不该产出一个自信的人格标签，它随后会随画像摘要
   进入每一次调用。反过来，回包点名一个本次没交给它的记录（`per_node` 里的 id 不在样本集内）
   是答得离谱，不是盘上读不回：在本包丢掉那一行。带下去只会让一次抄错 hex 被下游报成
   「一条记录读不回」，而那种拒绝每轮都会重来一次。**没答到契约上之后的那次格式重试
   自己失败时，交回的是它那一档码**（被取消 / 被端点拒），第一次那份解析错误只留在因果里：
   把「重试没跑成」说成「模型答非所问」，下游就会去查一个从没拒绝过它的模型，
   而真正该停下这一轮的那一档（取消）就此消失。

7. **prompt 里的数字与预算都来自注入方**：一次调用的输出预算不得超过 `Chat` 声明的端点
   上限——越过去是一次被端点直接拒掉的请求，那一轮就此不写。巩固目标条数这类数字同样由注入方
   交进来：写死在本包里，模型就会去压一个配置中并不存在的目标，为凑数合并不同主题——那是
   假记忆，比少合一组贵得多，所以任何数字都排在「不同主题禁并」这条之后。

每个能力包自带同包单元测试；改算法必须带测试并同步更新本文件的分工条目。
