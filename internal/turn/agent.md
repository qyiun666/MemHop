# internal/turn — 轮次沉淀小方法

- **职责**：`Targets`（Update 入参校验 + 场景/话题 ID 解析）、
  `SettleTarget`（纯函数：`TopicID` 必须是该场景已开出的轮次）、
  `WriteArchives`（一轮的原文落成该话题名下的两个内容槽位）、
  `ReadProfile`（Search 的 L0 读面，未建立按空画像）。
- **契约**：提炼（llmops）在根的大方法里做且排在任何写入之前；本包只做
  校验与记录读写。归档槽位是**位置式**的——用户说的占 `Seq=1`、回复占
  `Seq=2`，id 由 `core.HashContent(topicID, seq)` 派生，所以同 `TopicID` 重放
  = 原地覆写：本包不需要先问「这个话题现在有哪些归档」，也没有退役清单。
- **陷阱**：覆写只覆盖它写的那两个槽位。重放一轮时若少写了一条，另一条旧文本
  仍留在盘上，转录会多出一句已撤回的回复；库不追踪「本轮写了哪几条」来回收
  （那又是一份第二真相），收敛路径只有 `DeleteTopic` 或过 7 天保留窗。
  归档的归属只有一个来源——域内的 `ac.L4` 镜像，所以删归档必须在磁盘删成功
  之后摘镜像（`repo.DeleteTopicArchives` 内置了这一步序），否则该话题之后每次
  读都会撞「索引点名已不存在的记录」而硬错。
  `SettleTarget` 不读记录、只按规则判定（`k` 从 1 到场景 `TurnSeq` 逐个派生轮次
  id 比对，轮次数量级下成本可忽略）：Dream 融合父节点与轮次 id 同为 depth-1、
  同属一个场景，只能靠派生式区分——靠读记录区分会把「读失败」和「不是轮次」
  混为一谈。
