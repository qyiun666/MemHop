# internal/turn — 轮次沉淀小方法

- **职责**：`Targets`（Update 入参校验 + 场景/话题 ID 解析）、
  `SettleTarget`（纯函数：`TopicID` 必须是该场景已开出的轮次）、
  `PriorArchives`（本话题已拥有的归档，读 `ac.Arch`）、`WriteArchives`
  （一轮的原文落成该话题名下的归档）、`DropRetained`（旧档案墓碑差集）、
  `ReadProfile`（Search 的 L0 读面，未建立按空画像）。
- **契约**：提炼（llmops）在根的大方法里做且排在任何写入之前；本包只做
  校验与记录读写。同 `TopicID` 重放 = 覆盖（先问该话题已有哪些归档 →
  写新归档 → 墓碑差集），保证"一轮恰好两条原文"在改写文本的重放下成立。
- **陷阱**：归档的归属只有一个来源——域内的 `ac.Arch` 镜像，本包不再从
  记录上读引用清单，所以删归档必须在磁盘删成功之后摘镜像
  （`repo.DropArchivesL4` 内置了这一步序），否则该话题之后每次读都会撞
  「索引点名已不存在的记录」而硬错。`SettleTarget` 不读记录、只按规则判定
  （`k` 从 1 到场景 `TurnSeq` 逐个派生轮次 id 比对，轮次数量级下成本可忽略）：
  Dream 融合父节点与轮次 id 同为 depth-1、同属一个场景，只能靠派生式区分——
  靠读记录区分会把"读失败"和"不是轮次"混为一谈。
