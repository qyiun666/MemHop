# internal/turn — 轮次归属与沉淀闸门

## 职责

- `SettleTarget`：判定一个话题 id 是不是该场景已开出的某一轮。
- `ReadProfile`：读域的 L0 画像，从未写过按零值。
- 本包只做判定：收到的已经是解析好的 id，不读内容，也不写内容。

## 契约

- 两个入口都不取锁，调用方持有 `ac.Mu`。
- `SettleTarget` 的判据是「该场景真开出过的某一轮」：`k` 从 1 到 `TurnSeq` 逐个派生
  轮次 id 比对，所以重放当前轮与结算更早一个已开出的轮都合法。调用方只交得出域自持
  的那一个键，于是这道闸从「验入参」退成「最后一道不变量」：两个自持字段正常时永远成对、
  且落在该场景真开出过的轮上，一旦对不上就是内部状态错乱，宁可在 LLM 之前拒掉。
- 已被融合组沉下的那一轮同样**放行**：本包只判「这个场景开出过这一轮吗」，那一轮此刻
  在哪一层不是这里的判据，写它的调用方自己从存量记录把位置带回来。拒的是融合父自己的
  id、别的场景的轮次，和没人发过的 id。
- 未建立的画像按零值返回，其余错误一律上抛：一次读不能悄悄少了画像还算成功。

## 陷阱

- 判定不读记录，只按派生式（轮次数量级下成本可忽略）：融合父节点与轮次 id 同为
  depth-1、同属一个场景，只能靠派生式区分——靠读记录区分会把「读失败」和「不是
  轮次」混为一谈。
- 归属闸只管沉淀这一侧：跨场景的陈旧键必须由 `SettleTarget` 拒，否则一次收束会落到
  别的场景的轮次上。内容写入不再问它——写的是域自持的那一轮，键不在调用方手里，
  「拼错一个 id」这类错误在路径上已经不可能出现。
