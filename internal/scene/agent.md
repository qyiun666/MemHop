# internal/scene — L2 场景记录的小方法

## 职责

- 读面解析：`ResolveExisting`（宿主点名场景时定位它）、`CurrentScene`（该域没自持场景时，从
  记录里恢复轮次计数器跑得最远的那个，平手取 id 小的——同一份记录两次恢复得到同一个场景）
  与 `Create`（一个场景都没有时新建），交回的都是**场景 id** 而不是那条记录——接着开轮的那
  一步本来就要把场景读回来推计数器，所以续用自持 id 的那条路不必再问一次在不在。三个入口
  只收数值 id：宿主那串 hex 在组合根就解开了。新建在本包公开：铸一个未占用的 id（`freshID`）、
  连锚点一起落**一条**记录——名字与锚点都是创建期字段，一次写入就把它们放好，不留「记录已在
  盘上而锚点还没写上」的那一步，也不留写完还要回读的那一次。
- 读面渲染：`SurfaceTopics`（一个场景的 depth-1 话题，按 `UserTimestamp` 排、平手比 id）、
  `ContextTopic`（把一个话题的关键词轨、子话题数、它自己的两个时间界与递给它的原文渲染成一个场景条目；
  两个界随行走，是因为正文被保留窗扫空之后，行上只剩这些还能说）。
- 删除步：`DeleteCascade`（场景记录与话题记录 + 它们名下的内容 + 话题开出的计划树 +
  各份缓存）、`DetachGraph`（清掉命名某张 L3 图的锚点）。

## 契约

- 全部入口在调用方持有 `ac.Mu` 时被调用。
- `freshID` 只在 `ErrNotFound` 时认作 id 可用：IO / 关闭 / 损坏必须原样上抛，
  否则会铸出一个与活场景相撞的 id。
- `ResolveExisting` 在宿主点名场景、又同时递来锚点（`anchored`）时拒绝：锚点是创建期字段，
  改锚点只走 `UpdateScene`；丢掉一个锚点不得让它看起来已被采纳。这道拒绝只看入参，不看那张图
  在不在——先查图会把「场景已在这里」报成「记录不存在」（宿主去找一条自己从没要读的记录），
  还要在调用方的域锁里多付一次公共域读。
- 锚点校验一律经 `repo.ReadSharedGraphL3`，本包不自己读图槽；命名的图
  必须能解析。`Create` 先解锚再落记录：解不开就一字节不写——被拒路径上那个新铸的场景 id
  不会交回调用方，留下的就是一条宿主指认不了的 `session:<id>`。
- `DeleteCascade` 吃调用方严格枚举出的 id 清单，自己只剩一次全域枚举（计划树按 `TopicID`
  归因），它排在第一张墓碑之前：枚举不全时这一次删除盘上原封不动，代价全部落在被拒一侧。
  之后的三步都只照给定 id 落墓碑、不读 payload，还能拒绝的就只剩引擎关闭与 IO，而**顺序决定
  这种拒绝留下什么**：最深的记录先删，场景与话题记录的墓碑殿后（L2Meta 与计划树两份镜像的
  摘除更在最后，内容镜像随它镜像的那批内容一起走）。越过
  那次墓碑，调用方的入口就再也找不到它要删的场景（重试只剩 `ErrNotFound`），而缓存仍把它名下
  的话题列着——一条既删不掉也看不懂的半成品。

## 陷阱

- `ContextTopic` 按递给它的顺序渲染，不重排：原文的次序是读的那一侧按 `Seq` 给的，
  这里再按时间戳排一次会把一轮的问答打乱，而按 `Role` 打平更糟——事件的 `Role` 未设
  即 0，正是 `RoleUser`，那样一次工具调用会显示成用户发言。`Seq` 只是随每条原文带出去
  的槽位号：本包不从空洞推「哪一条被收走了」，那个空间与事件共用，判据不在渲染这一层。
- 被下沉的子话题（depth 2）只从 `ContextTopic` 出现：`SurfaceTopics` 交回的是整条话题
  （`Name` 也在里面），但它只列 depth-1。
- `DetachGraph` 按域全扫场景：锚点只长在场景上，图槽没有反向清单。它扫的是**严格**那一份
  ——扫出来的就是接下来要被改写的场景，跳过一条读不回的是留下一条指着已删图的锚点。
  扫出来的是解好的整条 slot，改写它即可；按 id 再读一次只多付一次解码，而它那条失败分支
  在调用方持锁下永不成立，读起来却像真有一种「扫到了又读丢了」的状态。
- 改写失败不停下这一趟：逐条收下来、走完整个域再一起报。停在第一条上，后面的场景就留在
  一个这一趟之后再没人来清的锚点上，而已经清掉的那些也回不来——半趟比一整趟失败更难看懂。
- `freshID` 跳过 0（id 面的哨兵值）并在占用时重铸；`Create` 的名字一律库生成
  `session:<id>`。
